# Components

- **Cards:** `article` is the classless card ([elements/\_article.scss](../src/scss/elements/_article.scss)), with optional `header` and `footer`. The look comes from the `card` mixin, shared with `dialog`, with local `--_card-*` properties at its top. The card grid lives in the layout stylesheet.
- **Buttons:** [elements/\_buttons.scss](../src/scss/elements/_buttons.scss) holds `button` and the input button types (`button` uses `cut-corner-border`), plus the grouping rules. Adjacent form controls drop the cuts where they touch (`:is(button, input, select, textarea)` adjacency, with `button` always the subject, since void elements have no pseudo-elements). The fill is the mixin's `::after`, so states set `--lunar-cut-bg` rather than `background-color`, and the host background must stay transparent. Group spacing comes from the layout stylesheet.
- **Checkboxes and radios:** [elements/\_checkboxes.scss](../src/scss/elements/_checkboxes.scss) and [elements/\_radios.scss](../src/scss/elements/_radios.scss). Both replace the native control with `appearance: none` and are drawn entirely on the element — `input` is void, so there are no pseudo-elements. The checkbox knob is a gradient moved with `background-position` and colored through `color` (gradients can't transition, `color` can). The radio fill is a `conic-gradient` whose stop is the registered `--lunar-radio-fill`; registering it with `@property` is what makes it animatable.
- **Range, progress and meter:** [elements/\_range.scss](../src/scss/elements/_range.scss), [elements/\_progress.scss](../src/scss/elements/_progress.scss) and [elements/\_meter.scss](../src/scss/elements/_meter.scss). Each is as tall as `--lunar-control-height`: the bar takes two thirds (`--lunar-bar-height`), the gap and ticks the rest. The ruler comes from the `ruler` mixin (8 ticks, none on the edges). Range has real track pseudo-elements in every engine; progress and meter only have them in WebKit, so in Firefox the track is the mixin's `$track` background layer, since a background can't carry a border or rounded corners. Range fills up to the thumb only in Firefox (`::-moz-range-progress`); WebKit has no equivalent. Meter colors the fill by state: success, warning, then error.
- **Tables:** [elements/\_tables.scss](../src/scss/elements/_tables.scss). No cut corner: `display: table` and pseudo-elements don't mix well, and a wrapper that scrolls would clip it. `thead th` draws the `ruler` mixin per cell, with `$start: true` marking where each column begins. Cells use `tabular-nums`, so digits line up down a column. The `tfoot` `striped` band is painted on the row group so it runs across cells without seams, with its first row padded below it. Both backgrounds opt out of forced colors.
- **Color:** [elements/\_color.scss](../src/scss/elements/_color.scss). The swatch is masked to a droplet icon, so the chosen color paints the shape. The mask is a URL-encoded data URI (not base64: smaller and readable in a diff), kept in a Sass variable at the top of the file, and applied to the swatch pseudo-element (`::-webkit-color-swatch` / `::-moz-color-swatch`) — never to the input, which would take the focus ring with it.
- **Details and summary:** [elements/\_details.scss](../src/scss/elements/_details.scss). Adjacent `details` join into one list: only the last keeps the bottom margin. The end marker is two `currentColor` gradients on `summary::after`; open collapses the vertical one to size 0. Hover and focus grow the `brackets` mixin's marks through `--_bracket-size`. Opening animates `::details-content` height (`interpolate-size: allow-keywords` plus `content-visibility … allow-discrete`); browsers without it just show the content.
- **Blockquote:** [elements/\_blockquote.scss](../src/scss/elements/_blockquote.scss). The `striped` mixin sets only `background-image`, so `background-size` and `background-position` confine it to a band (`--_quote-band`) down the left edge. The tinted panel is `::before`, starting `--_quote-gap` after the band, since a `background-color` would fill the gap too. The panel carries `bracket-*()` layers on its right corners only (`$corners`). No italic: Space Grotesk ships none, so the browser would synthesize one.
- **Pre:** [elements/\_pre.scss](../src/scss/elements/_pre.scss). It scrolls sideways, and `cut-corner-border`'s pseudo-elements would scroll with the content, so the corners are cut with `clip-path` (`cut-corner-polygon()`) on the `pre` itself, and everything drawn is a background layer (`background-origin: border-box`): the `bracket-*()` layers, inset clear of the cuts, plus four corner diagonals that continue the border where the clip cuts it. `code` inside `pre` is reset here. A scrolling `pre` is focusable: focus turns its muted border and diagonals accent through the registered `--_pre-edge`, so both transition together. There's no outline, even in forced colors, since the clip would cut it off; the edge shows there instead (`pre` opts out of forcing, and accent maps to `Highlight`).
- **Code, kbd, samp, var:** one partial each ([\_code](../src/scss/elements/_code.scss), [\_kbd](../src/scss/elements/_kbd.scss), [\_samp](../src/scss/elements/_samp.scss), [\_var](../src/scss/elements/_var.scss)). `code` and `kbd` use `cut-corner-border` on all four corners with a small `$size` (`code` with its border in the fill color), and `white-space: nowrap`, since the pseudo-element layers only frame a single line box. `pre code` restores `white-space` and drops the layers.
- **Paragraph:** [elements/\_p.scss](../src/scss/elements/_p.scss). The left brackets (`bracket-*()` with `$corners`) sit outside the text: backgrounds can't paint outside the box, so `p` reaches left by `--_p-offset` with a negative margin and pads it back, and `max-width` adds the offset so the text width is unchanged.
- **Mark:** [elements/\_mark.scss](../src/scss/elements/_mark.scss). The top-right cut is `clip-path` (`cut-corner-polygon()`) on the mark itself, not `cut-corner-border`: there's no border to continue across the cut, so it needs no pseudo-elements or `nowrap`, and a highlight can wrap. On a wrapped mark the clip follows the bounding box of all its lines, so only the corner of that box is cut.
- **Spacing between elements:** there's no generic `* + *` rule. Each element carries its own bottom margin (media included), and vertical margins collapse. The one exception is `section + section` ([elements/\_section.scss](../src/scss/elements/_section.scss)): a section's last paragraph has no bottom margin and headings have no top margin, so adjacent sections need a top margin. It matches the layout stylesheet's `--lunar-layout-gap` default, so the two collapse into one gap. A generic sibling rule would also double the gaps in grid cards, which are flex columns, where margins don't collapse.
