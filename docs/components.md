# Components

- **Cards:** `article` is the classless card ([elements/\_article.scss](../src/scss/elements/_article.scss)), with optional `header` and `footer`. The look comes from the `card` mixin, shared with `dialog`, with local `--_card-*` properties at its top. The card grid lives in the layout stylesheet.
- **Buttons:** [elements/\_buttons.scss](../src/scss/elements/_buttons.scss) holds `button` and the input button types, plus the grouping rules. All of them are cut with `clip-path` on the element itself (`cut-corner-polygon()` with a map of per-corner cuts, `--_cut-top-right` and `--_cut-bottom-left`, both from `--lunar-cut-size`), so input buttons get the cut too and `::before`/`::after` are free; anything drawn with them is clipped to the shape. The edge is the border plus `cut-edge-*()` diagonals across the cuts, all in `--_button-edge`: transparent at rest (it keeps buttons the size of the fields), the border color on reset. Focus can't use an outline, which the clip would cut off, so it turns the edge `--lunar-fg` and doubles it: the diagonals' stroke via `--_button-edge-width`, the straight edges with an inset box-shadow, since the border can't grow without resizing the button. Adjacent form controls drop the cuts where they touch: the group rules set one corner's cut to `0px` (not `0`, which `calc()` can't subtract from `100%`), and a button in the middle matches both. A field (`input`, `select`, `textarea`) right before a button drops its right-hand radius, so it joins the button square: the field rules read their right-hand corners from `--_field-end-radius`, and the group rule sets that to `0`, since the text-field selector (nine `:not()`s) would outrank a plain `border-radius` override. Group spacing comes from the layout stylesheet. Labels are smaller than field text, so buttons set `min-height: var(--lunar-control-height)` to stay level with the fields they group with. In forced colors the clip is dropped for a plain bordered rectangle.
- **Checkboxes and radios:** [elements/\_checkboxes.scss](../src/scss/elements/_checkboxes.scss) and [elements/\_radios.scss](../src/scss/elements/_radios.scss). Both replace the native control with `appearance: none` and are drawn entirely on the element — `input` is void, so there are no pseudo-elements. The checkbox knob is a gradient moved with `background-position` and colored through `color` (gradients can't transition, `color` can). The radio fill is a `conic-gradient` whose stop is the registered `--lunar-radio-fill`; registering it with `@property` is what makes it animatable.
- **Range, progress and meter:** [elements/\_range.scss](../src/scss/elements/_range.scss), [elements/\_progress.scss](../src/scss/elements/_progress.scss) and [elements/\_meter.scss](../src/scss/elements/_meter.scss). Each is as tall as `--lunar-control-height`: the bar takes two thirds (`--lunar-bar-height`), the gap and ticks the rest. The ruler comes from the `ruler` mixin (8 ticks, none on the edges). Range has real track pseudo-elements in every engine; progress and meter only have them in WebKit, so in Firefox the track is the mixin's `$track` background layer, since a background can't carry a border. Only range is rounded: the track uses `--lunar-radius-md` and the thumb `--lunar-radius-sm`, set explicitly because Firefox's default thumb is round. Progress and meter stay square, since Firefox has no track pseudo-element to round. Range fills up to the thumb only in Firefox (`::-moz-range-progress`); WebKit has no equivalent. The progress and meter fills are the `striped` mixin with no background color, so the track shows between the stripes. Progress stripes are muted. Meter picks the stripe color by state (success, warning, then error) through `--_meter-fill`: WebKit has a fill pseudo-element per state and sets it there; Firefox has one fill and a state pseudo-class on the host, so it sets it on the host and the fill inherits it. Since the stripes go through the mixin, the `--lunar-stripe-*` overrides reach the fills too, and an inherited `--lunar-stripe-color` replaces the meter's state colors.
- **Tables:** [elements/\_tables.scss](../src/scss/elements/_tables.scss). No cut corner: `display: table` and pseudo-elements don't mix well, and a wrapper that scrolls would clip it. `thead th` draws the `ruler` mixin per cell, with `$start: true` marking where each column begins. Cells use `tabular-nums`, so digits line up down a column. The `tfoot` `striped` band is painted on the row group so it runs across cells without seams, with its first row padded below it. Both backgrounds opt out of forced colors.
- **Color:** [elements/\_color.scss](../src/scss/elements/_color.scss). The swatch is masked to a droplet icon, so the chosen color paints the shape. The mask is a URL-encoded data URI (not base64: smaller and readable in a diff), kept in a Sass variable at the top of the file, and applied to the swatch pseudo-element (`::-webkit-color-swatch` / `::-moz-color-swatch`) — never to the input, which would take the focus ring with it. When disabled, the droplet is painted `--lunar-muted` whatever the value, so a value that matches the page can't vanish. The browser sets the swatch's `background-color` inline, so a flat `linear-gradient` layer covers it rather than an `!important` override (separate rules per engine, since a list mixing the two vendor pseudo-elements would be dropped).
- **Details and summary:** [elements/\_details.scss](../src/scss/elements/_details.scss). Each `details` is bordered, and adjacent ones join into one list: only the last keeps the bottom margin, each after the first pulls up by `--lunar-border-width` so neighbours share one border, and only the ends of the run are rounded (`:not(details + details)` on top, `:not(:has(+ details))` at the bottom), so separate groups and lone details each get their own ends. The summary's bottom border only shows while open, dividing it from the content. The end marker is two `currentColor` gradients on `summary::after`; open collapses the vertical one to size 0. Hover and focus grow the `brackets` mixin's marks through `--_bracket-size`. Opening and closing fade `::details-content` (opacity, with `content-visibility … allow-discrete` so it stays rendered while closing) and animate its height, which needs `interpolate-size: allow-keywords` (Chromium); elsewhere the height jumps but the fade still runs, and browsers without `::details-content` just show the content. The reduced-motion rule in the reset can't list `::details-content` (an engine that doesn't know it would drop the whole selector list), so `details` turns its transition off itself.
- **Blockquote:** [elements/\_blockquote.scss](../src/scss/elements/_blockquote.scss). The `striped` mixin sets only `background-image`, so `background-size` and `background-position` confine it to a band (`--_quote-band`) down the left edge. The tinted panel is `::before`, starting `--_quote-gap` after the band, since a `background-color` would fill the gap too. The panel carries `bracket-*()` layers on its right corners only (`$corners`). No italic: Space Grotesk ships none, so the browser would synthesize one.
- **Pre:** [elements/\_pre.scss](../src/scss/elements/_pre.scss). It scrolls sideways, and `cut-corner-border`'s pseudo-elements would scroll with the content, so the corners are cut with `clip-path` (`cut-corner-polygon()`) on the `pre` itself, and everything drawn is a background layer (`background-origin: border-box`): the `bracket-*()` layers, inset clear of the cuts, plus a diagonal at each of the two cut corners (top-right, bottom-left) that continues the border where the clip cuts it. `code` inside `pre` is reset here. A scrolling `pre` is focusable: focus turns its muted border and diagonals accent through the registered `--_pre-edge`, so both transition together. There's no outline, even in forced colors, since the clip would cut it off; the edge shows there instead (`pre` opts out of forcing, and accent maps to `Highlight`).
- **Code, kbd, samp, var:** one partial each ([\_code](../src/scss/elements/_code.scss), [\_kbd](../src/scss/elements/_kbd.scss), [\_samp](../src/scss/elements/_samp.scss), [\_var](../src/scss/elements/_var.scss)). `code` uses `cut-corner-border` on the top-right and bottom-left corners and `kbd` on all four, each with a small `$size` (`code` with its border in the fill color), and `white-space: nowrap`, since the pseudo-element layers only frame a single line box. `pre code` restores `white-space` and drops the layers.
- **Headings:** [elements/\_headings.scss](../src/scss/elements/_headings.scss), one partial for `h1`–`h6`. `h1` to `h3` carry a mark of slanted bars, one per level (`$heading-bars`: 1, 2, 3); `h4` to `h6` have none. The mark is a single `::before`, absolutely placed in the heading's left padding (so wrapped lines line up with the first) and centred on the first line with `top: calc(1lh / 2)`; `::after` is free. Its `clip-path` is one polygon holding every bar: each a parallelogram with its acute corners cut, joined by a bridge that runs there and back along the same line, so it encloses no area. The geometry is Sass constants in `em`, so the mark scales with the level; the points are computed in Sass, since `calc()` can't divide one length by another. The mark opts out of forced colors. The showcase hero's SVG `h1` drops the mark and its padding.
- **Paragraph:** [elements/\_p.scss](../src/scss/elements/_p.scss). The left brackets (`bracket-*()` with `$corners`) join into one full-height bracket through `bracket-sizes()`'s `$vertical-size: 100%`, and sit outside the text: backgrounds can't paint outside the box, so `p` reaches left by `--_p-offset` with a negative margin and pads it back, and `max-width` adds the offset so the text width is unchanged. The bracket reaches `--_p-extend` past the text at both ends (vertical padding, like the address), kept small since the padding adds to the gap between consecutive paragraphs.
- **Address:** [elements/\_address.scss](../src/scss/elements/_address.scss). Mono text in full-height brackets on both sides (`bracket-*()` on all four corners with `$vertical-size: 100%`), `width: fit-content` so the right one hugs the text; it reaches left like the paragraph, so the text lines up with paragraphs. The brackets reach `--_address-extend` above and below the text (vertical padding), with `space-4` margins above and below so they don't run into neighbours. The left bracket's per-line ticks are one layer as tall as the text (the box minus the padding): a `repeating-linear-gradient` with a stroke across the middle of every `1lh`, so it follows the line count, and no tick lands in the padding however far the brackets reach. Opts out of forced colors.
- **Mark:** [elements/\_mark.scss](../src/scss/elements/_mark.scss). The top-right cut is `clip-path` (`cut-corner-polygon()`) on the mark itself, not `cut-corner-border`: there's no border to continue across the cut, so it needs no pseudo-elements or `nowrap`, and a highlight can wrap. On a wrapped mark the clip follows the bounding box of all its lines, so only the corner of that box is cut.
- **Popover:** [elements/\_popover.scss](../src/scss/elements/_popover.scss). `cut-corner-border` with the top-right corner only; `position: fixed` and the rest sit in a `& { … }` block after the `@include`, as in `dialog`, so they override the mixin's `position: relative`. No box-shadow, which would show as a rectangle past the cut. Its `::before` and `::after` opt out of forced colors, like the cards'.
- **Lists:** [elements/\_lists.scss](../src/scss/elements/_lists.scss), one partial for `ul`, `ol`, `li`, `dl`, `dt`, `dd`. `ul` bullets are `ul > li::before`: a tick `--_list-tick` long, longer with each nesting level (`space-3`, `space-4`, `space-5`), right-aligned `space-2` from the text so every length ends at the same place, and centred on the first line. The native marker is hidden with `list-style-type: ""` rather than `list-style: none`, which makes Safari drop the list semantics for VoiceOver. `ol` uses three `@counter-style`s (`lunar-decimal`, `lunar-alpha`, `lunar-roman`: zero-padded decimal, then letters, then roman numerals, each with a `/` suffix), with the marker in the mono font; the padding is wider to fit it. `dl` is a two-column grid (`fit-content(50%) 1fr`): every `dt` takes column 1 and every `dd` column 2, so several definitions stack under one term, and `dl > div` groups are `display: contents`. The `dt` leader is the inline trick used for text-following rules: an inline-block `width: 100%` with `margin-inline-end: -100%`, cut at the edge by `overflow-x: clip`, drawn with `dotted`; the `dt`'s right padding is its minimum length, so the longest term, which sets the column width, still gets one. A flex row would split inline markup in a term (`dfn`, `code`). The ticks and leader opt out of forced colors. The layout stylesheet turns the ticks off in `nav > ul`.
- **Spacing between elements:** there's no generic `* + *` rule. Each element carries its own bottom margin (media included), and vertical margins collapse. The one exception is `section + section` ([elements/\_section.scss](../src/scss/elements/_section.scss)): a section's last paragraph has no bottom margin and headings have no top margin, so adjacent sections need a top margin. It matches the layout stylesheet's `--lunar-layout-gap` default, so the two collapse into one gap. A generic sibling rule would also double the gaps in grid cards, which are flex columns, where margins don't collapse.
- **Fieldset and legend:** [elements/\_fieldset.scss](../src/scss/elements/_fieldset.scss). The fieldset is a bordered, padded box (with `min-width: 0` over the UA's `min-content`). The legend is floated at full width, which turns it from the notch-in-the-border box into an ordinary block, and `legend + *` clears it. Negative margins of `--_fieldset-padding` pull it out to the border on the top, left and right, and the same padding puts its text back in line with the fields. Its text sits in a `striped-label` rule, whose lead is the fieldset padding minus the gap, so the text lines up with the fields. A floated legend isn't the "rendered legend", so `display: flex` works on it. `fieldset[disabled]` dims the legend; browsers disable the fields themselves.
- **Links:** [elements/\_a.scss](../src/scss/elements/_a.scss). The whole chip is drawn on the `a` with `box-decoration-break: clone`, so a wrapped link gets it on every line: a positioned `::before` can't, since an inline split across lines gives it a containing block from the first line's start to the last line's end, which collapses to zero width. The tint is a background layer and the accent line is `border-bottom`. The top-right cut is in the gradient, not `clip-path` (which would cut only the corner of the box around all the lines): at an explicit angle a gradient's 0% line runs through its starting corner, so `225deg` with a hard stop at `cut × 0.7071` gives a 45° cut `cut` long on each side, per line. The hover/focus sweep is an accent copy of the same layer on top, its `background-size` growing from `0` to `100%` wide from the left; the cut rides its leading edge and meets the chip's own at full width. Links in headings drop the chip (no tint, no padding) and keep the underline and the sweep: heading lines use `--lunar-leading-tight`, shorter than the font's content area, so a wrapped heading's inline boxes overlap and each line's tint would cover the underline of the line above. `::after` is the `target="_blank"` arrow: a URL-encoded SVG mask painted in `currentColor`, with `content: "" / " (opens in a new tab)"` alternative text (the plain `content` line before it is the fallback); it opts out of forced colors so the mask keeps its color. In forced colors, a link inside an element that opts out (a paragraph, a card header) inherits the opt-out and keeps its chip, with the sweep in `Highlight`, so hover and focus turn its text `HighlightText`, and the transition is dropped so the text never sits on `Canvas` mid-sweep. `::before` is free. The reset's `a:not([class])` rule is wrapped in `:where()` so it doesn't outrank these.
