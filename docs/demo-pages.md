# Demo pages

- **[src/demo.html](../src/demo.html)** is a fictional company (Acme Robotics, made-up data) showing the theme on a realistic landing page. It must stay **completely classless** — no `class` attributes, no inline styles, no showcase CSS. Anything it can't express means the theme is missing something; fix the theme, don't add page CSS.
- **[src/index.html](../src/index.html)** is the showcase and may use classes; the production theme may not. Every `.demo-box` gets a highlighted source preview beside it, generated at build time by [vite/demo-source.js](../vite/demo-source.js): it takes the element's own inner HTML, formats it with Prettier, highlights it with Shiki (Catppuccin Latte/Mocha, deduped into a few generated `light-dark()` classes) and wraps both in `.demo`. Adding `demo-wide` to a `.demo-box` makes that demo full width with the source below. Never hand-write demo code blocks; edit the demo markup and the preview follows. The showcase ships no highlighting JS or CSS.
- **`showcase.scss`** is **layout only**: width, spacing, flex/grid and alignment. No colors, borders or typography, so the showcase shows the theme as-is. The one exception is the hero ([showcase/\_hero.scss](../src/scss/showcase/_hero.scss)): the `h1` is an inline SVG with "LunarCSS" set into a square grid of dots, beside the intro copy. The dots are one path of zero-length round-capped segments, minus the dots the letters overlap; that list was worked out from Space Mono Bold's outlines at the text's size and position, so changing either means redoing it. An SVG filter gives the dots and letters the same inner and outer shadow. It doesn't `@use "main"`, because the theme is linked separately.
- **Social tags:** [src/index.html](../src/index.html) carries Open Graph, Twitter card and canonical tags. Two placeholders remain, flagged in a comment in its `<head>`: the origin (`https://lunarcss.example.com`) has to become the real host everywhere it appears, and `public/og-image.png` (1200×630) has to be added — previews need absolute URLs, so a relative path won't do. The demo page gets none of these on purpose: it isn't meant to be shared, only linked from the showcase.
- **Indexing:** the demo carries `<meta name="robots" content="noindex, follow">`, so its made-up company content stays out of search results while links back to the showcase are still followed. `public/robots.txt` (copied to `dist/` by Vite) deliberately leaves the page crawlable — a blocked page can't be read, so its `noindex` would never be seen, and the URL could still be listed from inbound links.
- Both pages share [src/theme-toggle.js](../src/theme-toggle.js) (buttons opt in with `data-theme-toggle`), plus a tiny inline head script that applies the saved theme before first paint. On the showcase the toggle is an icon-only button fixed at the top right with a back-to-top button beside it ([showcase/\_page-controls.scss](../src/scss/showcase/_page-controls.scss)); back to top fades in once the page scrolls (scroll-driven animation), and the toggle's SVG morphs from sun (page dark) to moon (page light) with CSS transforms, keyed on `data-theme` or, without it, `prefers-color-scheme`.
