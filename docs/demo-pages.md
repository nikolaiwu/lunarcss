# Demo pages

- **[src/demo.html](../src/demo.html)** is a fictional company (Acme Robotics, made-up data) showing the theme on a realistic landing page. It must stay **completely classless** — no `class` attributes, no inline styles, no showcase CSS. Anything it can't express means the theme is missing something; fix the theme, don't add page CSS.
- **[src/index.html](../src/index.html)** is the showcase and may use classes; the production theme may not. Every `.demo-box` gets a highlighted source preview beside it, generated at build time by [vite/demo-source.js](../vite/demo-source.js): it takes the element's own inner HTML, formats it with Prettier, highlights it with Shiki (Catppuccin Latte/Mocha, deduped into a few generated `light-dark()` classes) and wraps both in `.demo`. Adding `demo-wide` to a `.demo-box` makes that demo full width with the source below. Never hand-write demo code blocks; edit the demo markup and the preview follows. The showcase ships no highlighting JS or CSS.
- **`showcase.scss`** is **layout only**: width, spacing, flex/grid and alignment. No colors, borders or typography, so the showcase shows the theme as-is. It doesn't `@use "main"`, because the theme is linked separately.
- **Indexing:** the demo carries `<meta name="robots" content="noindex, follow">`, so its made-up company content stays out of search results while links back to the showcase are still followed. `public/robots.txt` (copied to `dist/` by Vite) deliberately leaves the page crawlable — a blocked page can't be read, so its `noindex` would never be seen, and the URL could still be listed from inbound links.
- Both pages share [src/theme-toggle.js](../src/theme-toggle.js) (buttons opt in with `data-theme-toggle`), plus a tiny inline head script that applies the saved theme before first paint.
